## 0. 为什么需要 v2.6.0（C-1 复述）

**C-1 循环论证**：根信任由本系统自举——被保护公钥（验 human gate 签名用）与作证的 `CONTRACT.md` 指纹同处**可改写域**。完全失控的管理员（同时持文件 + 代码写权限）可重写 `human-guard.json` + `CONTRACT.md` + `integrity.json`，绕过全部机制。绝对根信任层未闭合，故**永不**声称「无需人类在环 / 系统自主可控 / 闭环可控自指（无人类）」。

**v2.6.0 目标**：把根信任从「系统自举」改为「外部不可伪造锚点」，闭合 C-1。属**密钥后端级改动**，与 M-5 强交互。

## 1. 两条外部锚路线

### A. 硬件令牌（YubiKey / TPM）— PKCS#11 / WebAuthn
- 私钥**不出设备**、物理触碰 + PIN 才签名；Agent 无私钥、无物理触碰，无法伪造锚。
- 根信任锚 = 令牌密钥，由**设备证明**背书（YubiKey 证明证书链至 Yubico 根 / TPM EK→AK 证明），取代 `CONTRACT.md` 自证指纹。
- **改动点**：
  - 密钥生成：本地 RSA-2048 口令加密私钥 → 令牌内生成或令牌导出公钥、私钥留设备。
  - 签名（`human gate` / `bind_human_signature` / `resign`）：TTY 口令解锁 → 令牌 presence + PIN 仪式。
  - 验签：用令牌公钥；公钥真伪由设备证明背书，非自写 `CONTRACT.md`。
- **优点**：真正外部不可伪造锚点，最硬地破 C-1。
- **风险 / 代价**：
  - 可用性：设备遗失 / 损坏须有 **fail-closed + 人类闸**的密钥轮换 / 恢复路径（其本身是新攻击面）。
  - 多设备（家里 / 办公室）同步：每设备需独立令牌或共享 HSM。
  - 成本；CI 不可测（需令牌 / HSM 模拟器跑测试，真机检查列为人工步骤）。

### B. 人工带外强制 fail-closed
- 每次关键签名强制人类**带外**核验指纹 / 外部确认动作，不通过即 fail-closed。
- 锚 = 人类独立确认（信道**独立于可改写域**，如纸质 / 第二通道），Agent 无法伪造。
- **优点**：无硬件、快落地。
- **风险**：仍依赖人类勤勉；若人「点了过」则退化；本质是「人在环」显式化 + fail-closed，**未去掉人**。
- **诚实边界**：B 把根信任外置到人，但锚仍是人——严格说 C-1 为「部分闭合」（外部化但未去人），须如实披露。

### 推荐
- 要真正闭合 C-1（去系统自举）：选 **A**。
- 要低成本先消除「自证」循环：可 **A + B 混合**（令牌为主、带外为人丢失时的恢复闸）。

> **【已选定】KK 决：A + B 混合**。令牌为主根锚（破 C-1 的硬路径）；人工带外 fail-closed 作为令牌遗失 / 损坏时的恢复闸与二级锚。两条路径任一通过即视为根信任外部化成立；二者皆失才 fail-closed 阻断。
